## Design Specificity Verdict

The tinted-shadow system, magnetic buttons, and hidden Easter eggs (logo click-count, footer triple-click, Konami hint) are real authored choices. But the on-page copy is generic dev-portfolio filler ("Crafting elegant solutions through code," "A selection of projects that showcase my skills and passion for building great software") that never mentions the actual differentiator PRODUCT.md claims — the two real blog posts on auth strategy and concurrency/idempotency lessons. The "documented learning journey" positioning exists in the blog, not on the homepage that's supposed to sell it.

## Overall Impression

The design system is real and consistently executed — tinted shadows, the serif/mono pairing, and the Easter-egg layer all match what DESIGN.md describes. What's actually broken is trust-critical plumbing sitting directly under a confident-looking surface: the one way to contact this person is a dead mailto link that reports fake success, a "disabled" button silently still works, and a database outage looks identical to "nothing built yet." For a site whose entire job is proving credibility to recruiters in the first few seconds, the biggest opportunity is closing that gap between how put-together the surface looks and how unreliable the plumbing underneath it currently is.

## What's Working

1. The tinted-shadow/warm-paper system is executed faithfully, not just documented. shadow-soft/card/hover never fall back to neutral black, and cards pair the hover shadow with a -translate-y-1 lift exactly as DESIGN.md specifies — a real, consistent signature.
2. Hero CTA hierarchy is correctly weighted — a filled primary ("View My Work") against an outline secondary ("Contact Me"), a small but real restraint against making every button look equally important.
3. The Easter-egg layer is thoughtfully scoped — debounced, low-intensity, genuinely hidden rather than advertised (logo click-count, footer triple-click, Konami hint), which fits the "signal personality without undercutting credibility" brief.

## Priority Issues

- [P0] The only contact path on the homepage is dead and lies about success. personalInfo.email is ""; the footer's email icon copies an empty string to the clipboard while showing "Email copied! Ready to paste," and the rendered href="mailto:" confirms it reaches the DOM with no address. Why it matters: this is the single highest-stakes action for the recruiter half of the audience, and the false-success toast means a visitor won't even realize it failed. Fix: populate a real contact email now, or hide the email icon and route "Contact Me" to LinkedIn/GitHub until one exists — never show success for an action that did nothing. Suggested command: /impeccable harden

- [P0] A visually-disabled CTA is still fully clickable. EmptyState's "Check back soon" is Button asChild disabled wrapping a real Link; disabled doesn't apply to an anchor, so the dimmed/"not-allowed"-styled control still navigates. Why it matters: this is exactly the control a visitor sees when Featured Projects or Latest Posts render empty — a control that looks broken but isn't lying about it is a trust hit on a credibility-critical page. Fix: render a non-interactive span/div for the disabled state instead of Button asChild wrapping a live Link. Suggested command: /impeccable harden

- [P1] Homepage motion never checks prefers-reduced-motion, contradicting the project's own documented rule. DESIGN.md: "Do gate any new motion on prefers-reduced-motion, matching every existing GSAP/CSS animation in the codebase." The helper prefersReducedMotion() exists and is used elsewhere, but the hero's entrance timeline, its infinite chevron bounce, both scroll-triggered card reveals, the nav's magnetic-link tracking, and the scroll-triggered confetti all fire unconditionally on the homepage. Why it matters: a real, verifiable gap between stated intent and shipped code, and a genuine vestibular-motion concern on the first page every visitor lands on. Fix: wrap every homepage GSAP call and the confetti trigger in the existing prefersReducedMotion() check. Suggested command: /impeccable harden

- [P1] A Supabase fetch failure and "no content yet" render identically. Both getFeaturedProjects() and getBlogPostsSummary() catch all errors and return [] with only a server-side console.error; the homepage then shows the same "coming soon" empty state either way. Why it matters: a recruiter can't tell "hasn't built anything" from "the site is broken right now," and both readings hurt the credibility the site exists to establish. Fix: surface (or log to PostHog) a distinct signal when the fetch itself errors, so an outage doesn't read as an empty portfolio. Suggested command: /impeccable harden

- [P2] Eyebrow-label color contradicts the documented Singular Accent Rule. DESIGN.md reserves Muted Teal for eyebrow/kicker labels, but both homepage kickers ("Featured Work," "Blog") use text-primary (blue) — the hero's availability badge correctly uses teal, so the inconsistency is homepage-section-specific. Fix: either change the two kickers to text-accent, or update DESIGN.md's rule to match the code's actual choice — right now the doc and the app disagree. Suggested command: /impeccable polish

- [P2] Duplicated page title. Rendered title is "Tsholofelo Ndawonde | Tsholofelo Ndawonde" — layout.tsx passes the person's own name into a template that appends the site name, and both happen to be the same string. Why it matters: a recruiter glancing at a browser tab or search result sees a visibly broken-looking title. Fix: pass no title override on the root layout (let it fall back to the plain SITE_TITLE) or give the homepage a distinct, non-duplicated title. Suggested command: /impeccable polish

## Minor Observations

- Scroll-cue text uses text-muted-foreground/60 — low-severity legibility dip on decorative hint copy; easy to bump to /80.
- No skip-to-content link before the fixed nav pill; keyboard users tab through 5 links + 2 icons before reaching page content on every load.
- ProjectCard/BlogCard titles use line-clamp-2 with no title attribute for the truncated case, so a very long title's overflow has no hover/tooltip recovery.
- Footer's "System Operational" status pill is static/hardcoded flavor text, not a real system-status indicator — harmless, but worth knowing it's decorative.
